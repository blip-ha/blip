# Contributing to Blip

Thanks for helping. Blip grows one sensor at a time, built by people who own that sensor.

## Who builds what

- **The maintainer** adds the sensors they own, and maintains the app, the catalog and the modes.
- **You** can add a sensor you own, if it's approved: listed under **Help wanted** in [SENSORS.md](SENSORS.md).
- Not listed? Open a **New sensor proposal** issue. The maintainer decides whether it's eligible and adds it to the catalog. Sensors that don't detect people, or that give Home Assistant nothing to draw, aren't eligible.

## What a contributor pull request may change

To keep Blip safe for everyone, a pull request from a contributor may only:

| Change | Why it's allowed |
|---|---|
| **Add** `profiles/<id>.json` | A profile is data, not code, and is checked against `profiles/schema.json` |
| Update `SENSORS.md` and `.github/ISSUE_TEMPLATE/sensor_request.yml` | Regenerated by `npm run catalog`; CI checks they match exactly |
| Update `custom_components/blip/frontend/blip-panel.js` | Rebuilt by `npm run build`; CI rebuilds it and checks it matches exactly |

The **Contributor guard** check blocks anything else: app code, CI, the catalog, the schema, or edits to an existing profile. It runs from the protected main code, so a pull request can't change it. If your sensor needs something more, like a mode Blip can't draw yet (Cone, Map, Regions), open an issue first. The maintainer builds or reviews that code, and approves it with the `maintainer-approved` label.

## Adding a sensor

1. Find your sensor under **Help wanted** in [SENSORS.md](SENSORS.md). Its catalog id (in `catalog/sensors.json`) is your file name.
2. Look up how Home Assistant sees it: **Settings → Devices & services → Devices →** your sensor. Note the manufacturer, model, model ID and the entity ids.
3. Copy `profiles/aqara_fp300.json` to `profiles/<id>.json` and fill it in. [profiles/README.md](profiles/README.md) explains every field. The `match` rules must name your model, not just its manufacturer.
4. In `frontend/`:

   ```bash
   npm install
   npm test                # includes the schema check for your profile
   npm run catalog         # moves your sensor to Supported in SENSORS.md
   npm run catalog:check   # eligibility and safety checks
   npm run build           # rebuilds the panel with your profile
   ```

5. Test on your own Home Assistant: copy `custom_components/blip` into your `config/custom_components/`, restart, open Blip. Check that your sensor is found and that the aim test and band edits behave.
6. Open a pull request and fill in the checklist.

The checks catch the common problems: a model that isn't approved, a mode or integration that doesn't match the catalog, or `match` rules that would also claim another model's devices.

## Bugs and ideas

Use the **Bug report** issue form. Include your Blip version (bottom of the Blip page) and your Home Assistant version.
